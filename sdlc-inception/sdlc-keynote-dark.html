What it costs

Pain points

  • Feedback arrives only at acceptance testing
  • Change after sign-off is expensive
  • Testing gets squeezed at the end

Section 5 / Acceptance

Given, When, Then

Real world anchor
Written before the code

Each criterion states a context, an action and an expected outcome - so it can only pass or fail.

Principles
  • Cover the happy path, the edge cases and the errors
  • Each criterion becomes at least one test
  • No criterion, no test - no test, not done

Section 5 / Worked example

S2.1 · Find a document by ID

As a department user (Priya)  I want to ask the chatbot for a document by its ID  so that I can find its location without raising a ticket to engineering.
#CaseGiven / When / Then
1FoundGiven invoice 1234 exists · When Priya asks where it is · Then the bot answers with its location and a link
2Not foundGiven no document 9999 exists · When she asks for it · Then the bot says it was not found and does not guess
3AmbiguousGiven 1234 exists as both an invoice and a contract · When she asks for “1234” · Then the bot asks which type she means
4Invalid inputGiven an ID with invalid characters · When she asks · Then the bot explains the expected format
5Platform downGiven the platform does not respond within 3 s · When she asks · Then the bot says the archive is unreachable and offers to retry

NFRs: p95 under 3 s for the tool call · read-only · document ID logged, user PII not logged  ·  Story points: 5
