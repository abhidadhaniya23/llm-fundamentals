1M: brief down, structured result up

call_search_agent, call_debugger_agent (Coordinator) and call_reupload_agent (C) are Python tools.
Brief built in code from the schema-validated tool arguments: goal, ids, expected output, scope. Agent.run() sends it as the sub-agent's only user message.das/team.py 133-171, das/agent.py 52-55
JSON checked against a schema. The final answer must match SEARCH_OUT, DEBUG_OUT, …, with one repair attempt. It goes back to the caller as an ordinary tool result.das/agent.py 92-105
Written into SessionMemory: search_result, debugger_result, batch_id, reason_code, fault.das/team.py 139-158

3Gateway as the common pipe

Every tool result from every agent goes through Gateway.call.
Sanitises results: removes instructions embedded in the data (guardrails.sanitize).das/gateway.py 123-128
Collects ids into session.known_ids. The output guardrail only lets the Coordinator reply and C's notify_user cite ids in that set.das/gateway.py 129-130, das/team.py 241

4Bounded consult B → A

Not a real A run: consult_search_exists calls the helper exists_in directly, is allowed once (consult_once), records it in ctx.run["consults"], and the record is passed up to the Coordinator.das/tools.py 74-83

2Why the lock

Parallel writes: the Coordinator runs A and B in parallel threads, and both write to session, so writes happen under state.lock.das/agent.py 116-125
