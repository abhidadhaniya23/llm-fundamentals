Workflows & Agents · hand-rolled, no framework

Seven exercises, and every step is an agent

These are the exercises from Building Effective Agents with LangGraph, with the same inputs: cats, LLM scaling laws, "3 and 4". They're rebuilt in plain Python on labs/shared.py, with no LangGraph or LangChain.

Workflow

Your code sets the path. LLM calls fill in the steps along it.

Agent

The model chooses its next action, sees the result and chooses again until it's done.

The harness · shared.run_agent

An agent is a loop you can read in one screen

  • Tools are plain functions. Their signature and docstring are the description the model reads.
  • The protocol is JSON in the prompt, not a provider's native tool API, so it works the same on Nexus and Claude.
  • validate is how code gets the last word. If an agent skips a check, it gets the error back and tries again.
  • Tool errors are sent back to the model too, so a bad call doesn't crash the run.

Labs 01–05 run two ways

Every step is an agent. Who decides the order?

workflow

Predictable: every run takes the same path, and you can test each step on its own.

Use it when you can write the order down in advance.

agentic

Flexible: the lead agent can skip a step, redo one or ask again with a better brief.

Use it when the next step depends on what the last one returned.

Either way

Code checks the final answer. In agentic mode, code also records what the sub-agents really returned, so the lead can't claim results that never happened.

wf00 · Augmented LLM

One call can format a query. Finding the answer takes a loop.

In the notes

with_structured_output(SearchQuery) on "How does Calcium CT score relate to high cholesterol?", and bind_tools([multiply]) on "2 times 3". Each is one call.

Here

Part 1 does both by hand. Part 2 gives the question to a research agent. A mock search returns a mix of on-topic and off-topic results, so it has to read, judge and sometimes search again.

Code checks
  • The answer matches the ResearchAnswer schema (pydantic).
  • Every cited id was really read: read_result is wrapped so code records each read.
Try this

Ask about "calcium and bones" instead. The search returns W05, an off-topic result. Watch whether the agent cites it.

wf01 · Prompt chaining

A chain of agents, with a gate in code between them

In the notes

Topic → write a joke → gate: does it contain "?" or "!"? → add wordplay → add a twist. Three single calls.

Here

Same chain, but the joke must use a real cat fact, be original (word overlap with 40 known jokes under 0.5), stay kid-safe and be at most 40 words. The model can't check any of that without tools.

Code checks
  • The gate stays in code, exactly as in the notes: no punchline means the run stops.
  • Wordplay's output must still be original. The Polisher's output must pass every final check.
  • In agentic mode, the Editor's final joke must pass the same checks.
Try this

Change the Writer's prompt to "retell a classic cat joke". Watch check_originality push back.

wf02 · Parallelization

Three writer agents at once, then an agent that checks their facts

In the notes

Topic → joke, story and poem in parallel → an aggregator that concatenates the strings.

Here

Each piece has its own rules: the story is 150–200 words with ≥2 real facts, the poem is a limerick (AABBA, checked in code), the joke is original. The aggregator is an agent that checks every fact id the pieces claim with get_fact.

Code checks
  • Each writer's validator: word range, limerick rhymes, originality, real fact ids, kid-safe.
  • The combined output must have all three headings.
  • dispatch isolates failures: one writer failing doesn't stop the others.
Try this

The Poem Writer rewrote its first limerick before handing it in. Make the rhyme check stricter in wf_tools.rhymes and count the retries.

wf03 · Routing

"Cats lol" can't be routed until the router knows who sent it

In the notes

"Write me a joke about cats" is classified as joke, story or poem. The request already names its route.

Here

Five requests from different readers, most of them vague ("something for tonight, they love our cat"). The router agent looks up each reader's age, likes and things to avoid, picks a route and writes a brief for the writer.

Code checks
  • step must be one of poem | story | joke (a pydantic Literal).
  • In agentic mode, the piece the user gets comes from the writer that was called, not from the router retelling it.
Known limit

Omar "likes long reads", but the story writer is capped at 200 words. Try making the length part of the brief.

wf04 · Orchestrator-worker

The plan comes from what the library holds, and every claim needs a source

In the notes

"Create a report on LLM scaling laws": plan the sections, use Send() to start one worker per section, join the results. The workers write from memory.

Here

A library of 9 papers (Kaplan, Chinchilla, emergence, the "mirage" paper, data-constrained, inference-aware, test-time compute, …). The planner looks at what's there. Each worker reads its papers and cites them as [paper-id].

Code checks
  • The plan has 3–5 sections, and every paper id it uses exists.
  • Each section cites only papers that exist and that this worker read.
  • The references list is built in code from the citations.

A worker that cites a paper it never opened is the multi-agent version of a hallucinated source. Here code catches it.

wf05 · Evaluator-optimizer

"Funny" becomes a rubric the evaluator has to check with tools

In the notes

Generate a joke → grade it "funny" or "not funny" with feedback → loop until funny. The grade is pure taste.

Here

A five-rule rubric: original, based on a real fact, kid-safe, ≤40 words, a real surprise. The evaluator runs the checks with tools instead of guessing, and its feedback names the rule that failed.

Code checks
  • The evaluator's answer must be Feedback{grade, feedback}.
  • Agentic mode, trust but verify: the joke handed in must be one that grade_joke graded "funny", word for word. Code keeps its own record of every grade.
Try this

Remove the final check in agentic mode and ask the Generator to "just hand in your best one". Does it skip the grade?

wf06 · Agent

The model plans the steps; tools do every lookup and every sum

In the notes

"Add 3 and 4. Then, take the output and multiply by 4." The LLM node, the tool node and a should_continue edge. That's the warm-up here.

Here

A cat café in Bergen orders 3 bags of kibble and 2 scratching posts with code WHISKERS10. What's the total in EUR? The agent has to look up the rules, prices, discount, shipping, tax and exchange rate, then calculate in the right order.

Code checks
  • The final number must match a result an arithmetic tool returned. Mental arithmetic is rejected.
  • It must also equal cafe_total(), the same rules worked out in code.
Try this

Change the code to NEWCAFE (15% off, minimum subtotal 3,000 NOK). The subtotal is 2,265, so the discount shouldn't apply. Does the agent notice?

Check yourself

Where is the decision made?

wf01 workflow: who decides to stop when there's no punchline?

Your code. The gate is an if, just as in the notes. The agents only write.

wf03 workflow: the router picked "poem". Who runs the poem writer?

Code, through if/elif. In agentic mode the router calls the writer itself, and code checks that it really did.

Is wf05's workflow loop an agent?

No. The for loop and the "funny?" check are code. What's inside the loop are two agents. In agentic mode, the loop moves into the Generator agent.

Why not just trust the agent's final answer?

Because it can skip its tools. In the test runs, wf04 workers cited papers they hadn't read. validate sent them back to read before their sections were accepted.

What would LangGraph give you that these labs don't have?

Infrastructure, not patterns: checkpoints and memory, streaming, human-in-the-loop pauses, deployment. For checkpoints you could write your own; see 01b_sequential_agents_hardened.py.

One line to remember
The pattern

The pattern is the order of the steps: chain, fan out, route, plan, loop. It's plain code.

The agent

The agent is a loop inside a step: model, tool, result, repeat. It's about 50 lines of Python.

Give a step an agent when it needs tools to get the answer right. Then check the answer in code.
